# Dependency review: the Android JNI glue

ADR 0004 review for the direct dependency that ADR 0026 (section 4) adds to
`crates/fylo-ffi` for Android.

|                        | `jni` 0.22.4                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Purpose                | The Android entry points: Kotlin's `io.github.d31ma.fylo.FyloNative` calls `fylo-ffi`'s `jni_calls.rs`, which reaches the same calls as the C ABI. Kotlin cannot call a C ABI directly                                                                                                                                                                                          |
| Owning crate           | `fylo-ffi`, Android only (`cfg(target_os = "android")`)                                                                                                                                                                                                                                                                                                                         |
| Targets                | `aarch64-linux-android`, `x86_64-linux-android`; not built anywhere else                                                                                                                                                                                                                                                                                                        |
| Features               | Defaults off: no `invocation`, so FYLO never starts or loads a JVM (`java-locator`, `libloading` stay out)                                                                                                                                                                                                                                                                      |
| License                | MIT OR Apache-2.0                                                                                                                                                                                                                                                                                                                                                               |
| New transitive crates  | None in `Cargo.lock`: `jni` 0.22.4 and its dependencies were already there through `rustls-platform-verifier` (`fylo-machine`'s Android path). In the phone library they are new code: `jni-sys`, `combine` (with `bytes`, `memchr`), `simd_cesu8` (with `simdutf8`), `log`, `thiserror`, `cfg-if`; build-time only: `jni-macros`, `jni-sys-macros`, `rustc_version`, `walkdir` |
| Unsafe and native code | `jni` wraps the JVM's C interface, so its own code is `unsafe`; it is upstream, reviewed like Turso's in ADR 0020. FYLO's glue calls only its safe API: `EnvUnowned::with_env`, `convert_byte_array`, `byte_array_from_slice`. The glue has no `unsafe` block; its only `unsafe` items are the `#[unsafe(no_mangle)]` export names (unsafe-inventory, Mobile C ABI row)         |
| Build script           | `jni-macros` and `simd_cesu8` run `rustc_version`; no network, no native build                                                                                                                                                                                                                                                                                                  |
| Panics and errors      | `with_env` attaches the thread, runs the call inside `catch_unwind`, and turns a JNI failure into a Java `RuntimeException` (`ThrowRuntimeExAndDefault`). A panic inside FYLO is caught first, by the same `CAbi::root_call` as the C ABI, so it answers `FYLO_PANIC` and kills only its handle                                                                                 |
| Untrusted input        | Java `byte[]` values from the app: copied into Rust, then checked as UTF-8 and as JSON by the same code as the C ABI. The answer is one new `byte[]`                                                                                                                                                                                                                            |
| Secrets                | None pass through `jni` today; S4's key value will arrive as a `byte[]` that FYLO copies into a zeroizing buffer                                                                                                                                                                                                                                                                |
| Maintenance            | jni-rs organization, active; the standard Rust JNI crate (used by `rustls-platform-verifier`, `android-activity`, Firefox's Android code)                                                                                                                                                                                                                                       |
| Removal path           | A hand-written C file built by the NDK that calls `fylo.h`: more FYLO-owned `unsafe` C code, which ADR 0026 avoided on purpose                                                                                                                                                                                                                                                  |

Binary impact (`bun run build:android`, `mobile` profile, stripped): the
arm64-v8a `libfylo_ffi.so` grew from 4,372,760 to 4,604,552 bytes (+231,792,
which also holds `fylo_find_page`); x86_64 is 5,454,720 bytes. The AAR is
4,613,746 bytes.
