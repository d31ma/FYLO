Native configuration

Configure the native Rust engine in application.json; keep secrets in an adjacent .env.

Settings under fylo

JSON key Purpose Default
fylo.root Filesystem root for collections ./.fylo-data
fylo.schema Directory containing JSON validation schemas —
fylo.strict Validate documents with chex before writes —
fylo.shard.width Trailing TTID characters used for newly created collection shards 1
fylo.encryption.key Secret reference for $encrypted fields (at least 32 UTF-8 bytes) —
fylo.cipher.salt Salt for blind index derivation —
fylo.chex.binary Path to the schema validator executable —

Process model

The fylo executable is the only native engine. JavaScript and the other language packages are thin NDJSON clients and never open a root directly. Use --exclusive-root for long-lived processes that require one authoritative owner.

Binary-backed SDK applications can select an application.json with the optional config path. Each FYLO child can use a different file without modifying global environment state. Browser and mobile clients retain explicit host options; they do not implicitly read local configuration or secret files.

Resolution and isolation

FYLO resolves native configuration in this order:

  1. Explicit constructor and command-line arguments.
  2. The selected application.json.
  3. Engine defaults.

The CLI discovers application.json in its working directory, or uses --config /path/to/application.json. Paths inside JSON resolve relative to that file. An absent default file uses defaults; an explicitly selected missing file, malformed JSON, invalid setting, or unresolved secret reference fails initialization. The former FYLO_* environment settings are no longer implicit overrides.

JSON settings, explicit secret references

{
    "fylo": {
        "root": "./data",
        "schema": "./schemas",
        "strict": true,
        "shard": { "width": 2 },
        "encryption": { "key": "${FYLO_ENCRYPTION_KEY}" },
        "cipher": { "salt": "${FYLO_CIPHER_SALT}" }
    }
}

Each underscore in a former setting becomes a nested key: FYLO_SHARD_WIDTH becomes fylo.shard.width. Keep only secrets in the adjacent .env. Configure the encryption key and cipher salt together as secret references, or omit both. Literal credentials in JSON are rejected. 

# .env beside application.json
FYLO_ENCRYPTION_KEY=replace-with-a-secret-of-at-least-32-characters
FYLO_CIPHER_SALT=replace-with-a-secret-salt

Exact whole-value ${NAME} references resolve from the inherited environment first, then the adjacent .env. Unreferenced variables are ignored. No shell commands, recursive expansion, or embedded interpolation are performed. Missing references fail with sanitized errors; resolution never mutates the process environment.

Configuration and binary paths are administrator-controlled bootstrap input. Never derive them from a request, tenant setting, upload, or job payload. Secret loading does not inject .env values into PATH or dynamic-loader variables. Never publish native secrets in website JSON or client bundles.

Keep populated files out of source control. Prefer a secret manager for credentials; when a file is required, add its exact name or pattern to the consuming application's ignore rules and make it owner-readable only (for example, chmod 600).

Installer and release-tool variables, including FYLO_VERIFY_PROVENANCE, are separate from engine configuration and remain unchanged.
